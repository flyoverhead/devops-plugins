# Changelog

## 2026-11-11

### Added

- Skill `post-patch-validation`: validates an existing security fix by running it. Inputs are a GitHub PR (read with `gh pr view` / `gh pr diff` after a host check), a fix commit, a branch pair or a binary-safe patch file; a non-GitHub remote or unusable `gh` gets one request for a range, branch pair or patch file. Steps: pin, coverage over four lenses, plan with all seven check kinds, an approval gate before any project code runs, run, two evidence reviewers, and a status of `NEEDS_REPAIR`, `BLOCKED`, `REVIEW_REQUIRED` or `READY_FOR_HUMAN_REVIEW`. Never approves a merge, never posts to GitHub without a yes, never touches real infrastructure.
- Runner `scripts/post_patch_validation.py` (Python 3.11+ stdlib, git 2.36+) with `scaffold`, `validate-plan`, `run` and `print-schema`. Pins commits, patch hash, changed files and submodules and refuses moved pins; rejects shell strings; runs side-blind exploit and variant checks in random order in randomly named, lease-locked worktrees with private scratch and plan copies; requires a bare `PPV_REACHED` stdout line; fixed minimal environment plus `--allow-env` with credential and loader-hijack names refused; archives helpers by SHA-256; writes `result.json` (schema 2.0), `report.md` and `artifact-manifest.json`; exits 0, 1, 10 or 64. Each stream is capped at 16 MiB (the run is cut, killed and reported as a gap) and scratch archives at 2000 files / 64 MiB; archival and hashing errors become gaps, worktrees are always disposed, and a crash after execution began exits 10. Leftover worktrees of a dead runner on this host are reclaimed only inside a runner directory under the temp root, with no global prune; Git LFS smudge filters are off for runner checkouts; submodules come only from local objects. `--allow-env` also refuses values with URL credentials and names such as `*_PAT`, `*_PWD`, `JWT`, `DSN`, `NETRC`, `KUBECONFIG`, `DOCKER_CONFIG`, `AWS_PROFILE`, while `GOPRIVATE`, `GONOSUMDB` and `GONOPROXY` pass.
- Agents `coverage-mapper` (one lens per agent: root-cause, behavior, adjacent-security, harness) and `evidence-reviewer` (coverage-completeness, evidence-integrity), both read-only.
- References: plan format with evidence levels, kinds and placeholders; variant hunting axes and rejected arguments; result, assessment and report formats.
- Tests: runner tests on temporary git repositories (ref and patch-file modes, reproducibility, ASCII locale, side-blindness and leak channels, env forwarding, archival, failing closed, concurrency, stale leases, submodules), assessment tests, CLI tests and plugin structure tests; `tests/run-all.sh`.
- Evals: a PR-fix trigger, a Go outcome where a one-shot replace misses repeated line breaks (a log-injection fixture of our own instead of an XSS one), an approval-gate outcome where nothing runs without an explicit yes, a read-only negative, and a non-GitHub-remote fallback.
- Every documented `git diff`, `git show` and patch-showing `git log` passes `--no-ext-diff --no-textconv`.
